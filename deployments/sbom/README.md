# Contract release SBOM artifacts

Generated by `scripts/generateContractReleaseSbom.ts` (V2-SC-088).

Do not commit secrets, private keys, or environment-specific credentials here.
Files are JSON SBOM + provenance attestations keyed by release version.

## Contents

Each release attestation is a single JSON document named `<release-version>.attestation.json` that inventories every build input immutably:

- **npm dependencies** — resolved name, version, integrity hash, and license from `package-lock.json`.
- **Foundry submodules** — subdomain path, commit SHA, and license from `.gitmodules`.
- **Compiler** — solidity compiler version and download checksum.
- **GitHub Actions** — pinned action references with full commit SHA.
- **Scripts** — SHa-256 digest of every script used during the build.
- **Source hashes** — SHA-256 digest of each contract source file.
- **Licenses** — license identifier for every dependency and source file.
- **Build artifact digests** — SHA-256 digest of each compiled artifact.

## Reproducibility

Run `npm run generate:sbom` on a clean checkout to regenerate the SBOM and provenance attestation. The generator fails
(exit code 1) when:

- a dependency is mutated after lockfile resolution,
- a dependency or source file is missing a license identifier,
- a source input is unpinned (floating tag or branch reference),
- a build artifact digest does not match the recorded checksum,
- any attestation field contains a secret or environment-specific credential.

The committed attestation must reproduce byte-for-byte on a clean checkout of the release tag.

## Submodule dependency provenance (PREWAVE-SC-067)

The recursive dependency graph (forge-std, OpenZeppelin, and nested submodules) is pinned and verified before any build. The gate is enforced by `scripts/verifySubmoduleProvenance.ts` and is never weakened.

The gate fails closed on any of the following:

- **SHA mutation** — a submodule commit differs from the pinned SHA in `deployments/submodules.lock.json`.
- **URL mutation** — a submodule URL differs from the approved upStream (including transport/protocol and host).
- **Missing nested module** — a nested submodule is absent from the resolved graph.
- **Dirty tree** — a submodule working tree has uncommitted modifications or untracked files.
- **Unreachable commit** — the pinned commit cannot be resolved from the registered remote.
- **License mismatch** — the detected license differs from the approved license recorded in the lock file.

A substituted or dirty content state fails the gate rather than producing an artifact.

## Release attestation

Each release attestation records the resolved submodule graph:

- *path** — submodule path relative to the repository root
- *url** — approved upStream URL
- *commit** — pinned full 40-character SHA, never a tag or branch
- *license** — detected and approved license identifier
- *nested** — recursive children with the same fields set

Attestations are keyed by release version and are immutable once published.

## Upgrade procedure

1. Update the desired submodule commit in `deployments/submodules.lock.json` to a full 40-character SHA resolved from the approved upStream URL.
2. Run `scripts/verifySubmoduleProvenance.ts` locally and confirm the resolved recursive graph matches the lock file with no dirty or substituted content.
3. Regenerate the SBOM and provenance attestation via `scripts/generateContractReleaseSbom.ts`.
4. Open a release PR including the lock file diff, the regenerated attestation, and the verification log.
5. Merge only after the provenance gate passes in CI and the release attestation records the new SHAs.
6. Never bypass or weaken the gate to force an upgrade through; fix the upStream or lock file instead.
