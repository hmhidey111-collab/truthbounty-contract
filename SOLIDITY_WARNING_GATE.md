# Solidity compiler warning gate

The gate is fed from Hardhat's Solidity standard-JSON build-info, not terminal text. `npm run warning-gate` cleans stale compiler outputs, performs a complete Hardhat compile using the version and settings in `hardhat.config.ts`, then reads all build-info records produced under `artifacts/build-info`. Every compiler diagnostic with severity `warning` is normalized to a source path, source line/column, compiler version, diagnostic code, and whitespace-normalized message; its SHA-256 fingerprint is independent of terminal formatting. Diagnostics are deduplicated and sorted. There is no generated-source exclusion: warnings from generated Solidity inputs and production Solidity inputs are treated equally. Build outputs such as artifacts are not compiler sources and are naturally absent from compiler diagnostics.

Accepted exceptions belong in `solidity-warning-baseline.json`. Each entry requires the exact warning identity plus `severity`, `rationale`, `owner`, and an ISO `expires` date. Expiry on or before the current UTC date fails, even if that warning is no longer emitted. A clean build needs no entries. Warnings may disappear without changing the baseline; removing obsolete baseline entries is allowed. New compiler warnings fail until deliberately recorded.

On pull requests, adding or changing an exception requires a maintainer to apply the `solidity-warning-baseline-reviewed` label. The CI workflow listens for label changes so that approval re-runs the check. Removing entries does not require that label. Baseline structure, normalized source paths, unique/sorted fingerprints, valid ownership/rationale/expiry, and matching fingerprints are validated on every run. Protect `solidity-warning-baseline.json` and the review label with the repository's normal branch-protection and maintainer permissions; the label is an explicit review signal, not a substitute for required human review.

Run the focused tests with `npm run test:warning-gate`. CI also runs the gate as part of the existing test job; the existing Foundry, fuzz, invariant, gas, and contract test gates remain unchanged. The warning inventory is the Hardhat compilation source set; Foundry still builds and tests its configured source set, but Foundry-only diagnostics (for example, a warning exclusive to a Solidity test) are not independently captured into this baseline yet.

## Current baseline and outstanding dependency context

The first clean build exposed a missing import in `contracts/TruthBounty.sol`: the file inherited OpenZeppelin `ERC20` but imported only `IERC20`. Adding the `ERC20` import fixed compilation without changing contract behavior or the deployment topology. The successful solc 0.8.28 build emits 13 warnings; all are individually represented in the baseline with a source identity, rationale, `protocol-maintainers` owner, and 2026-12-31 expiry. These are temporary exceptions rather than blanket suppressions. The additions intentionally require the `solidity-warning-baseline-reviewed` maintainer label in PR CI before they can be accepted.
